# PHẦN 2. CÔNG NGHỆ PHÁT TRIỂN

## 2.1. Công nghệ chính

- Ngôn ngữ: C#.
- Framework Controller: .NET Framework 4.8.
- Framework Client: .NET Framework 4.8.
- IDE: Visual Studio 2022.
- Giao diện: Windows Forms.
- Database: SQLite.
- Networking: TCP/IP, Socket.
- Security: TLS, AES-256, PBKDF2.
- Screen Capture: Windows GDI/BitBlt API.
- Mouse/Keyboard: Windows API SendInput.
- Image Encoding: JPEG, PNG.
- Video Compression: H.264 nếu khả thi và tương thích.
- Logging: NLog hoặc Serilog.
- Data Access: Repository Pattern.
- Asynchronous: async/await, Task, CancellationToken.

RDM Controller và RDM Client phải sử dụng .NET Framework 4.8.

RDM Relay Server có thể sử dụng ASP.NET Core chạy độc lập trên VPS hoặc Windows Server để đảm bảo khả năng triển khai và mở rộng.

Không tự ý chuyển Controller hoặc Client sang .NET 6, .NET 7, .NET 8, .NET 9 hoặc .NET 10.

Mọi thư viện NuGet phải được kiểm tra tương thích với .NET Framework 4.8 và các phiên bản Windows mục tiêu.

## 2.2. Hỗ trợ CPU

Bắt buộc hỗ trợ:

- x86 – 32-bit.
- x64 – 64-bit.

Tạo các cấu hình:

# PHẦN 3. KIẾN TRÚC HỆ THỐNG

Thiết kế hệ thống theo kiến trúc ba thành phần độc lập.

## 3.2. RDM CLIENT

Ứng dụng cài trên máy tính được điều khiển.

Chức năng:
- Tự động tạo Remote ID duy nhất.
- Đăng ký với RDM Server.
- Hiển thị Remote ID.
- Cho phép thiết lập mật khẩu truy cập.
- Cho phép bật/tắt Remote Access.
- Chấp nhận hoặc từ chối yêu cầu kết nối.
- Hỗ trợ Unattended Access khi chủ máy chủ động cấu hình.
- Chụp và truyền màn hình.
- Nhận lệnh điều khiển chuột và bàn phím khi được cấp quyền.
- Truyền file.
- Chat.
- Hiển thị thông báo đang có phiên điều khiển.
- Có nút ngắt kết nối khẩn cấp.

Phải xử lý đúng Session 0 Isolation, UAC và quyền truy cập desktop. Không được giả định Windows Service có thể trực tiếp chụp hoặc điều khiển desktop của người dùng.

## 3.3. RDM RELAY SERVER

Server trung gian triển khai trên VPS hoặc Windows Server.

Chức năng:
- Đăng ký Remote ID.
- Quản lý Client Online/Offline.
- Xác thực Controller.
- Xác thực Client.
- Điều phối kết nối.
- Quản lý Session.
- NAT Traversal.
- Relay dữ liệu.
- Quản lý nhiều kết nối đồng thời.
- Giám sát hoạt động.
- Logging.
- Quản lý thiết bị và thu hồi quyền truy cập.

Ưu tiên kết nối P2P có xác thực khi khả thi. Khi không thể kết nối trực tiếp, sử dụng Relay Server.

Relay Server không được có khả năng đọc nội dung dữ liệu khi phiên kết nối sử dụng End-to-End Encryption.

Không giả định TCP trực tiếp luôn hoạt động qua Internet.

# PHẦN 8. HỆ THỐNG MÃ HÓA VÀ BẢO MẬT DỮ LIỆU TOÀN DIỆN

Đây là yêu cầu có mức độ ưu tiên cao nhất của dự án.

Phải thiết kế Security Architecture độc lập, bảo vệ dữ liệu tại mọi thành phần.

## 8.1. Mã hóa dữ liệu truyền tải

Tất cả kết nối:

- Controller ↔ Relay Server.
- Client ↔ Relay Server.
- Controller ↔ Client P2P.

Phải được mã hóa.

Yêu cầu:
- TLS 1.2 trở lên.
- TLS 1.3 khi nền tảng hỗ trợ.
- Xác thực chứng thư Server.
- Kiểm tra Certificate Chain.
- Kiểm tra Hostname.
- Kiểm tra thời hạn chứng thư.
- Chống MITM.
- Chống Replay Attack.
- Không bỏ qua lỗi chứng thư trong Production.

Dữ liệu cần mã hóa:
- Remote ID và thông tin xác thực khi truyền.
- Dữ liệu màn hình.
- Lệnh chuột.
- Lệnh bàn phím.
- File.
- Chat.
- Session Information.
- Dữ liệu quản trị.

## 8.2. End-to-End Encryption (E2EE)

Đối với kết nối qua Relay Server, phải hỗ trợ mã hóa đầu cuối.

Relay Server chỉ chuyển tiếp dữ liệu đã mã hóa và không thể đọc nội dung:

- Hình ảnh màn hình.
- Lệnh điều khiển.
- Nội dung file.
- Tin nhắn Chat.

Sử dụng:
- Cơ chế trao đổi khóa an toàn.
- Xác thực khóa đầu cuối.
- AEAD.
- AES-256-GCM hoặc ChaCha20-Poly1305 khi được hỗ trợ.
- Nonce không được tái sử dụng với cùng khóa.
- Chống Replay.
- Có cơ chế thay đổi Session Key.

Phải xác thực khóa đầu cuối bằng chứng thư hoặc cơ chế xác minh khóa tin cậy, tránh Relay giả mạo khóa để thực hiện MITM.

## 8.3. Mã hóa dữ liệu lưu trữ

Các thông tin nhạy cảm trong SQLite phải được mã hóa:

- Password Credential.
- Token.
- Private Key.
- Session Key.
- Encryption Key.
- Thông tin chứng thư.
- Cấu hình nhạy cảm.
- Thông tin tài khoản.

Sử dụng:
- AES-256-GCM hoặc giải pháp mã hóa xác thực tương đương.
- Windows DPAPI để bảo vệ khóa.
- PBKDF2 cho mật khẩu xác thực.
- Secure Random Number Generator để tạo khóa.
- Key Rotation.
- Key Revocation.

Không lưu khóa mã hóa trực tiếp trong source code hoặc Database dạng Plain Text.

## 8.4. Key Management

Tạo module:

RDM.Shared.Security.KeyManager

Chức năng:
- Tạo Encryption Key.
- Quản lý Database Key.
- Quản lý Session Key.
- Quản lý File Encryption Key.
- Quản lý Authentication Key.
- Bảo vệ khóa bằng DPAPI.
- Thay đổi khóa định kỳ theo chính sách.
- Thu hồi khóa.
- Quản lý phiên bản khóa.
- Không ghi khóa vào Log.
- Hủy khóa Session trong bộ nhớ khi kết thúc phiên nếu có thể.

Không tái sử dụng cùng một khóa cho nhiều mục đích.

## 8.5. Bảo mật File Transfer

- Mã hóa file khi truyền.
- Kiểm tra SHA-256.
- Kiểm tra tính toàn vẹn.
- Chống sửa đổi dữ liệu.
- Chống chèn dữ liệu độc hại.
- Kiểm tra quyền thư mục.
- Chống Path Traversal.
- Xác nhận trước khi ghi đè.
- Xác nhận trước khi xóa.
- Có thể mã hóa file tạm.

## 8.6. Bảo mật Session

Mỗi Session có:
- Session ID riêng.
- Session Key riêng.
- Thời hạn.
- Xác thực hai đầu.
- Chống Replay.
- Thu hồi Session.
- Tự động hết hạn.

Khi Disconnect:
- Hủy Session.
- Thu hồi token liên quan.
- Giải phóng Socket.
- Hủy khóa Session trong bộ nhớ khi có thể.
- Không cho phép tái sử dụng Session cũ.

## 8.7. Bảo mật Relay Server

- Không lưu Password Plain Text.
- Không ghi nội dung màn hình vào Log.
- Không ghi nội dung file vào Log.
- Không thể giải mã E2EE.
- Có Authentication.
- Có Rate Limiting.
- Có chống Brute Force.
- Có chống Flood.
- Có Firewall Policy.
- Có Audit Log.
- Có thu hồi thiết bị.
- Có thu hồi token và chứng thư.
